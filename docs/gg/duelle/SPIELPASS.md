# Offener Abnahmeplan am wirklichen Produkt

**CODEX DRAFT — NOT CANON · GEPLANT. Noch kein ausgeführter Spielpass.**
Dieser Plan hält die noch fehlenden Handlungen fest. Er ersetzt keinen Lauf.

## Voraussetzungen vor dem ersten Lauf

GG übergibt einen festen, geprüften Helferstand für den lokalen SQL-Prüfstand (echte Datenbankabfragen und Speicherung auf der Platte), beauftragt in cgo-009. Eigene Kopie und eigene neue Datenwurzel, zwei synthetische Testklassen, getrennte Schüler- und Lehrerstarts. Nur die ausdrücklich erlaubten DEV-Identitätswege verwenden; keine Produktionsumgebung lesen und keinen Konto-Anmeldebeweis daraus ableiten. Fremdklasse muss abgewiesen werden. Vorher ebenfalls ausdrückliche Zuteilung für Installation, App-Bau, Server und umfangreichen Browserpass abwarten.

Die Hauptquellen bleiben am Startpin. Falls GG einen anderen Prüfstand verlangt, wird die abweichende Fassung gesondert genannt; keine stillschweigende Mischung von altem Entwurf und neuem Lauf. Jede Änderung an den eigenen Dokumenten oder dem Muster erhält einen neuen Kopfstand und passende erneute Prüfung.

## Eine Aufzeichnung pro Weg

Externes Protokoll enthält: Kopfstand, Rollenlauf, synthetische Klassenrolle (keine Zugangswerte), Adresse, Gerät/Browser, Fenstermaß, Eingabeart, Bewegungsmodus, Aufgabenkennung, Aktion, sichtbares Ergebnis, Bildpfad und Bild-MD5. Nur die tatsächlich ausgeführten Zeilen werden abgehakt. Vorher-/Nachherzustände beim Abbruch und Speichern sind verbindlich. Quellbelege und Laufbelege bleiben getrennt.

| Weg | Vollständige Handlungsfolge | Gezielte Gegenprobe |
|---|---|---|
| Auswahl/Hub | `/play` → eigener Jahrgang → angebotene Zone; zurück zum Hub | falscher Jahrgang und nicht freigegebenes Kapitel |
| Paint Einstieg | altes `buch` → richtige Kapiteladresse; Kapitelanfang → Welt | falsches Kapitel; Schüler kann Lehrer-/Entwurfstür nicht öffnen |
| Paint ruhige Begegnung | Wesen erreichen → Reiz ansehen → falsche Antwort → Hilfe → korrigieren → Weltwirkung | „Später“ vor Antwort, erneut ansprechen; verlorene Eingabe ehrlich protokollieren |
| Paint restore | Benennen → Weltveränderung/Farbzustand → Farbe → Rückkehr | Abbruch zwischen den beiden Schritten; keine doppelte Weltwirkung |
| Paint Rettung/Zeremonie | Käfig → richtige Rettungsrunde → nächste Runde → Ende | Abbruch in mittlerer Runde und erneut ansprechen: gleicher Weltzähler |
| Paint Tür | Tür ansprechen → Aufgabe → falsche Antwort → korrekt → Übergang | Abbruch öffnet nicht still die Tür |
| Paint Quickfire | Schwarm sowie vorhandene `scene.stage` getrennt erreichen → lesen → erste Eingabe → weiterer Eingriff → Lösung | Uhr steht vor Eingriff; Ablauf danach; reduzierte Bewegung ohne unsichtbare Uhr |

| Keen Welt/Lauf | Weltkarte → Kapitel-Lauf → reguläre Begegnungen → reguläre Boss-Tür → Ende → Welt | direkte `boss=1`-Vorschau getrennt aufnehmen; sie ersetzt den Türweg nicht |

| FOURTEEN J3 | Kapitel → Sprachaufgabe → falsch/verbessern → Kommentarzustand, wo vorhanden → nächste Szene → Abschluss | kein erfundener Wahlbildschirm; fehlgeschlagene Antwortübertragung darf nicht als bestätigt gelten |
| Y4 Entscheidung | freigegebene Auswahlstelle erreichen → eine Wahl → nächste Szene → Merkerwirkung → neu laden | Storywahl ohne Sprachurteil; Neustart liest wirklich gespeicherten Merker; verlorene Speicherung sichtbar |
| Detective / Welt-Dialog | tatsächliche Auswahlstelle bzw. Dialog-Aufgabe → Sprache beantworten → Erzählwahl → nächste Szene | Wahl und Sprachantwort im Versuchsprotokoll unterscheiden |
| Zusätzlicher Schulweg | angebotene Station unter Lehrer und freigegebenem Schüler getrennt → Antwort → Rückkehr | nicht freigegebene Schülerbahn/Fremdklasse ablehnen; nicht zum Sozialduell erklären |

Die zehn Paint-Kartenarten werden auf die wirklich erreichten Wege abgebildet. Fehlt eine Art im gewählten Kapitel, ist das eine offene Abdeckungszeile, keine stillschweigende Erledigung. Alle sechs Kapitel enthalten Entwurfs-/Freigabeunterschiede; Codeabdeckung aller Karten ist nicht Spielabdeckung aller Kapitel.

## Lokales geplantes Urteilsmuster separat

Bedeutungsvorbereitung ohne kartenspezifischen Schlüssel → fehlende Zustimmung verhindert Start → unbekanntes Material führt zurück zur Übung → beide bereit → erste Auswahl falsch → Quellvergleich → erneute Auswahl → Rollenwechsel → zweite Aufgabe → Rückschau. Zusätzlich Alleinweg, Pause nach Auswahl, Beenden aus Pause abbrechen und fortsetzen, bestätigtes Beenden, Neuladen. Zusätzlich alle 83 erfassten Texteinträge gegen die wirklichen Ansichten abgleichen: kein verlorener Tastaturfokus beim Ankreuzen, passende Sprache auch im Alleinweg, Hilfe verfügbar, keine kartenspezifische Lösung vor der Erstwahl. Die Zahl ist der Stand des gegenwärtigen Katalogs und wird nach Änderungen neu ermittelt. Ladefehler mit wirklich fehlender Musterdatei im eigenen temporären Testverzeichnis prüfen; keine Produktquelle sabotieren. Richtig, plausible mündliche Variante und Fehler nach `DIDAKTIK.md` prüfen. Getrennter kalter Löser erhält keine vorbereiteten Antwortbeispiele oder Quellenkommentare. Jede Aufnahme trägt sichtbar GEPLANT. Keine dieser Aufnahmen zählt für eine Produktzeile oben.

## Abschluss

Installation und alle 28 am Startpin ermittelten Pflichtbefehle erst nach Platzfreigabe ausführen, Ausgaben außerhalb des Repos. Tatsächliche Befehlsliste unmittelbar davor erneut aus `package.json` lesen; identische Befehle nur einmal. Keine Leistungsmesswerte bei reinem Dokumentdiff behaupten. Nicht erreichte Bedien-/Speicher-/Touchwege heißen UNVERIFIZIERT. Bei fehlender Pflichtprüfung keine vollständige Freigabe; fehlenden Punkt mit Beleg an GG statt an Koki geben.
